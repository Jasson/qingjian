本地实时翻译目前仅支持 macOS，缺省关闭。它使用本机运行的 Ollama，中文译为英文，英文译为中文，与候选旁的字词释义同时显示。

## 开启

1. 安装并启动 Ollama。
2. 在终端运行以下命令，下载翻译模型；下载完成后可退出命令行对话，保留 Ollama 服务运行：

   ```bash
   ollama run maternion/hy-mt2:1.8b
   ```

3. 打开青简「设置 → 中英文 → 本地实时翻译」，开启「实时中英互译」。
4. 「本机服务地址」保留 `http://localhost:11434`，「本地翻译模型」保留 `maternion/hy-mt2:1.8b`。修改输入框后按 `Enter` 保存，按 `Esc` 取消。

本机地址只允许指向当前电脑。此功能使用独立的本地翻译设置，无需填写 API 密钥；「云服务」页的云联想开关、地址与模型不影响它。它也不改变「候选」页所选的字词释义语言。

## 边输入边翻译

青简将本句已经上屏的文字与当前高亮候选合在一起预译，无需等到选字。继续输入、切换高亮候选或退格时，整句译文会重新调整，显示在独立悬浮条中。等待新译文时保留上次成功译文，并显示「更新中…」；第一次翻译才显示「翻译中…」。更新失败时保留上次译文并提示失败，切换应用或输入框后清空。每次更新替换当前句译文，不逐词拼接；选字上屏后，已参与预译的候选不会重复加入句子。

例如输入「我正在」，悬浮条先显示这段文字的译文；继续输入「学习英语」，译文根据完整的「我正在学习英语」修正。高亮候选尚未确认时，译文是预览，可能随选词改变。未写完的句子缺少上下文，模型可能误判含义。

中英混写时按整句的主要语言推断翻译方向，例如「API 接口需要鉴权」译为英文。随着输入增加，方向也可能重新判断；这类判断无法覆盖所有混写方式。

停止敲键约 180 毫秒后开始请求，实际等待时间取决于电脑和模型运行状态。继续输入会使旧请求失效，较早的结果不会覆盖最新文字。译文不会自动替换应用中的原文。可复制当前显示的译文，或在开启替换选中内容后手动确认替换对应原文。

## 复制与手动替换

浮窗中的「复制译文」按钮可复制当前显示的完整译文，也可按 `⌃⌥C`。「更新中…」或更新失败时，仍可复制浮窗中保留的上次成功译文；复制的内容与当前显示一致。

若需要将原文换成已有译文：

1. 在「设置 → 中英文 → 本地实时翻译」开启「允许用译文替换选中内容」，缺省关闭。
2. 完成选字并等待所需整句的译文出现。
3. 在同一个输入位置选中这段译文对应的完整原文。
4. 点击浮窗「替换选中内容」，或按 `⌃⌥R` 手动确认。

替换使用已经生成的译文，不会因为选中文字而重新调用模型。选中的文字必须与这段译文对应的原文完全一致，包括标点和空格；不能只选一个词，却用整句译文替换它。未选中文字或内容不匹配时，青简会提示并保留原文。

通过鼠标或键盘选中文字时，同一输入位置当前显示的那条成功译文会保留，便于与选中内容核对；更新中仍显示旧译文时，也只能用于与这条旧译文完全对应的原文。继续输入会重新开始追踪句子。切换输入框或应用、更改本地翻译设置、进入密码等私密输入环境后，这段记录会清除，需要重新输入并取得译文。开启开关不会自动替换任何文字。

应用还需允许替换选中的文字。青简会核对选中文字、输入位置及替换能力，通过后才尝试替换；若应用无法提供可靠选中文字或不支持替换，仍保留原文和复制功能。macOS 自带 Terminal 暂不支持此操作；终端历史输出通常也不可编辑，可使用复制译文。其他终端能否替换取决于应用提供的能力。

在「设置 → 中英文」中点击「修改替换快捷键」，可直接前往「快捷键」页并定位「用实时译文替换选中内容」录制器；同组也可修改复制快捷键。也可从「设置 → 快捷键 → 本地实时翻译」进入，修改两个组合键，仅接受修饰键加英文字母，不接受数字或标点；开始录制后按 `Backspace` 可禁用对应快捷键，浮窗按钮仍可使用。关闭「允许用译文替换选中内容」不影响复制。上述操作使用本机已有的实时译文，与「翻译选中文字」的云服务功能分开。

## 终端译文上屏（草稿模式）

此模式仅用于 macOS 自带 Terminal，缺省关闭。需先开启「实时中英互译」，再开启「设置 → 中英文 → 本地实时翻译 → 终端译文上屏（草稿模式）」。关闭时保留原有的直接输入方式；微信等其他应用的输入与选区替换方式不变。

开启后，原文先保留在青简草稿中，不直接写入 Terminal。浮窗同时显示原文和译文，空格、数字及方向键仍用于选字。完成选字、等待最新整段译文后，点击「输出译文」或按 `⌃⌥V`，才将译文一次性写入 Terminal。译文还在更新或更新失败时，不能输出旧译文代替当前草稿。

没有原文草稿与待选拼音、且未在翻译审阅或符号面板中操作时，单独按 `Space` 直接输入到 Terminal，不进入草稿。此类前导空格不会随后续草稿一同翻译或输出；已有草稿中的空格继续保留在草稿内，正在输入拼音时仍用空格选字。

浮窗提供四个操作：

- 「复制译文」：复制当前显示的成功译文，更新中保留的旧译文也可复制。
- 「输出译文」：输出与当前完整草稿一致的最新译文。
- 「输出原文」：输出已确认的文字，加上尚未选字的原始按键；不采用高亮候选，不把双拼按键展开成全拼。例如已确认「今天」、待选按键为 `shi`，输出「今天shi」。缺省快捷键为 `Enter`。
- 「取消草稿」：一次丢弃整段草稿与待选拼音，不向 Terminal 输出文字。缺省快捷键为 `Esc`。

普通 Mac `⌫` 优先删除正在输入的拼音／字母，待选按键删空后再删除已确认原文的末字。候选预览的汉字可能暂时不变，可查看浮窗中的「待选拼音」及光标位置，或候选窗口的拼音行；草稿模式下这行始终在青简显示，即使全局选择了「只在行内」。长拼音显示光标附近的按键，省略部分用 `…` 标出。删除后原文与译文会重新更新，原有译文在更新期间不能输出。本段说明的是普通 `⌫`，不是 `Fn + ⌫`／外接键盘的向前删除键。

普通 `⌫` 的系统接管只在 Terminal 位于前台、当前使用青简、实时翻译和草稿模式均开启且草稿或待选按键非空时生效；其他输入环境保持原有行为。不接管带 `⌘`、`⌥`、`⌃` 的删除操作，也不改变向前删除键。按住退格删空后，会等本次按键松开；再次按普通 `⌫` 时，空草稿状态按 Terminal 原有方式处理。

若浮窗提示无法接管退格，请按提示在「系统设置 → 隐私与安全性」检查青简相关授权，包括辅助功能、输入监控；具体是否可用以系统实际允许为准。青简不会自动弹出授权框或打开设置。安装更新后若再次提示权限，请按当前版本重新授权并重新激活；若旧授权未生效，可在辅助功能中移除旧青简条目，重新添加当前安装的青简，再重试。完成授权后，切换到其他输入法，再切回青简重试。若系统暂停退格接管，草稿会保留，也需重新激活青简重试；不会反复自动申请或强行恢复。接管不可用时，请查看浮窗中的待选按键和原文，确认是否实际删除，不以按键次数判断。重新激活仍会按本节的焦点切换规则清空草稿，需要保留的内容可先复制译文或输出原文。用户已设置的输出快捷键（例如 `⌘⇧Y`）不受此次退格接管影响。

有草稿或正在输入拼音时，缺省 `Enter` 直接输出上述「已确认文字＋未选原始按键」，不先确认高亮候选；缺省 `Esc` 一次取消整段草稿和拼音。两项可在「设置 → 快捷键 → 本地实时翻译」的「输出终端草稿原文」「取消终端整段草稿」分别录制修改，支持单独 `Enter`、单独 `Esc` 或修饰键加英文字母；开始录制后 `Esc` 会被录入，点击别处才取消录制，按 `Backspace` 禁用对应快捷键。

输出原文和取消草稿无需等待模型结果。「输出原文」「取消草稿」的键盘入口需要系统允许青简处理键盘事件，与普通退格接管使用相同的已有权限。若权限不足，按键会被青简接收并提示不可用，草稿不会清空或输出；仍可点击「输出原文」「取消草稿」按钮。请按浮窗引导检查授权，不能仅凭按键已被接收判断操作已经完成。

若更改或禁用原文输出快捷键，原来的 `Enter` 仅保留选字或提示行为，不会再输出原文。若更改或禁用整稿取消快捷键，原来的 `Esc` 可取消待选拼音或折叠候选，但不会再取消整段草稿；无待选拼音时会提示使用配置的取消操作或按钮。

输出原文或译文后清空草稿，不自动执行；此时没有草稿与拼音，用户可自行检查并按 `Enter` 正常提交给终端中的程序。空草稿状态下，`Ctrl + C` 等控制键和导航操作也按终端原有方式处理。

两种输出都按单行文字处理：换行转为空格，其他不可见控制字符会被拒绝。此模式只支持尾部追加、退格与选字，不是完整的文字编辑器；有草稿时，暂不支持的复杂导航会提示并保留草稿，可继续编辑、输出或使用当前配置的取消快捷键（缺省 `Esc`）主动取消。切换应用或输入焦点、修改相关设置、进入私密输入环境会清空草稿，不自动输出。它不依赖读取终端里已有的文字，也不替换选区。系统粘贴等绕过青简的操作仍由终端处理，草稿不接管终端里已有的文字。

「设置 → 快捷键 → 本地实时翻译 → 输出终端草稿译文」可修改 `⌃⌥V`，录制时按 `Backspace` 禁用；禁用快捷键后仍可点击按钮。已有自定义组合不会改回默认，例如 `⌘⇧Y` 可保留。

系统输出快捷键目前按 ABC／QWERTY 的物理字母键位登记，使用其他键盘布局时，实际按键位置与键帽字母可能不同。

输出快捷键由系统登记，也支持包含 `⌘`、`⇧` 的自定义组合；是否能够使用仍取决于系统是否允许登记该组合，不能保证抢占所有已占用的快捷键。仅在 Terminal 中使用青简、同时开启实时翻译与草稿模式且未处于私密输入环境时启用；离开该环境或关闭相关功能时释放。

若登记失败，浮窗会显示原因与系统状态码，仍可点击「输出译文」。解决冲突后，重新激活青简，或关闭再开启草稿模式，可重试登记。译文输出快捷键与「输出译文」按钮使用相同条件：先完成选字，并等待当前完整草稿的最新译文；「更新中…」时需继续等待，按键不会强制输出旧译文。

## 什么时候开始下一句

以下断句规则用于普通实时翻译。Terminal 草稿模式保留整段原文，包含句末标点，不按这些规则切成下一句。

- `。`、`.`、`?`、`？`、`!`、`！` 与明确换行结束当前句，之后从下一句重新翻译。
- `，`、`,`、`；`、`;`、`：`、`:`、`、` 保留在当前句中，不断句。
- 小数、常见英文缩写与网址、邮箱中的点按上下文判断；`3.14`、`Dr. Smith` 等不因中间的点切句。
- `…`、`……`、`...` 暂不结束当前句，避免犹豫或省略时过早切断上下文。
- 连续的 `?!`、`!!!` 作为同一句的结束标点处理；句末紧随的引号、右括号归入前一句。

若在连续输入中删除句末标点，前一句可恢复为当前句，继续输入时重新翻译。英文点号存在歧义，缩写与网址判断不能覆盖所有写法。

## 可用范围与异常

以下连续输入追踪说明适用于普通实时翻译，草稿模式的保留与取消规则见上节。

实时翻译跟随当前输入位置。切换输入框、切换应用，或出现无法确认的光标移动与外部编辑时，青简会停止当前句的连续追踪，从后续输入重新开始；不会将两个输入框的文字拼在一起。同一输入位置选中文字时保留最近成功译文，仅供复制和核对替换，不把选中文字当成新句重新翻译。一般应用中，能够确认输入框已清空时会清除旧上下文；鼠标修改旧内容、粘贴或应用自动改写后的整句同步可能受限。

未开启草稿模式时，macOS 自带 Terminal 按当前连续输入中已上屏的文字与高亮候选累计整句，不因屏幕回显变化、空白或与输入不一致而丢弃前半句。分几次选字上屏仍可连续翻译；这不表示青简能够读取 Codex 等终端界面中的真实编辑内容。鼠标移动输入位置、方向键导航、复杂删除、明确按回车提交、粘贴或自动补全后，原有内容可能无法继续准确追踪，需从后续输入重新开始。切换应用或输入框、更改本地翻译设置、进入私密输入环境时仍会清空对应记录。Terminal 可查看、复制译文，暂不支持用译文替换选中内容。

密码框与系统识别为私密的输入环境不参与翻译。当前句文字只发送到所填的本机 Ollama，不回退到云服务。若 Ollama 未启动、模型缺失或请求超时，正常打字仍可继续；启动服务或修正模型后再输入即可重试。

## 排查前半句丢失

保持默认日志级别即可，无需开启「详细日志」。先在同一输入位置分几次选字输入「我正在学习英语」，再在浏览器输入框中重复，并试一次清空后重新输入。若句子前半段仍丢失，打开青简菜单的日志目录，查找最近带有 `live_translation` 的记录；也可运行：

```bash
grep 'live_translation' "$HOME/Library/Logs/Qingjian"/qingjian.log.* | tail -n 60
```

若普通 `⌫` 仍无法编辑浮窗草稿，可按以下步骤收集默认日志，无需开启详细日志：

1. 保持 Terminal 在前台，确认实时翻译与草稿模式已开启；切到其他输入法，再切回青简，重新输入一小段测试文字。
2. 查找「退格入口诊断已开启」，随后正常输入应出现一次「IMK诊断入口活跃」。
3. 按一次普通 `⌫`，间隔至少一秒再按；也可按一次 `Fn + ⌫` 作对照，后者只用于诊断，不会改变当前删除规则。
4. 将同一 `session` 的「IMK退格入口诊断」与已有的退格处理记录一起核对。`BackspaceKey`、`ForwardDeleteKey` 分别表示观察到键码 51、117；`BackspaceControl`、`DeleteControl` 只表示观察到单一退格控制码，不能据此确定实体按键。`MissingEvent`、`MissingClient` 表示入口参数不完整。

新增入口诊断在每次草稿激活期间最多 16 条，没有十秒截止，不必赶时间；特殊类别首条立即记录，之后稀疏记录，长按重复会被抑制。额度用完后可重新激活青简再试。普通按键只留一次入口活跃标记及累计数量，不记录字母键码、字符或按键序列。已有的草稿编辑分支记录与这个新增额度分开。

这组诊断覆盖未处于草稿写入门禁、Host 暂时不可用及入口参数不完整的情况，只记录事件类别、删除键码、修饰位、状态与长度等元数据。若出现普通入口活跃标记，却没有对应删除记录，也只能说明这次诊断没有观察到对应事件形式；仍需结合状态继续分析，不能直接断言系统拦截。修改设置后若没有开启记录，重新切回青简即可开始新的诊断会话。

这组诊断记录只包含应用标识、范围、长度、可信度和重置原因，不包含输入或译文正文。`Partial` 表示应用仅提供局部信息，`Unreadable` 表示无法可靠读取；这两种状态不会仅因前文为空就清除已输入的句子。`Full` 表示已经核验过可读前文；`trusted_context_changed` 表示一般应用中检测到可信的内容变化，`commit_composition`、`activate`、`deactivate`、`mouse_event` 则分别表示系统结束组词、激活、失焦或鼠标操作触发实时输入上下文重置；同一输入位置为替换而保留的译文记录与此分开管理。Terminal 的屏幕文字仅用于诊断，不用于否定连续输入的句子；同样的系统分段通知也不直接清除 Terminal 的连续输入记录。记录这些原因有助于判断问题来自局部文本接口还是实际会话切换。
