本地实时翻译目前仅支持 macOS，主开关缺省关闭。开启后调用本机 Ollama，中文译为英文，英文译为中文，保留候选旁的字词释义。微信的已验证配置与独立草稿窗测试边界见下文。

## 开启

1. 安装并启动 Ollama。
2. 在终端下载翻译模型；下载完成后可退出对话，保留 Ollama 服务运行：

   ```bash
   ollama run maternion/hy-mt2:1.8b
   ```

3. 打开青简「设置 → 中英文 → 本地实时翻译」，开启「实时中英互译」。
4. 「本机服务地址」保留 `http://localhost:11434`，「本地翻译模型」保留 `maternion/hy-mt2:1.8b`。修改这两个输入框后按 `Enter` 保存，`Esc` 取消。

「翻译草稿模式」默认开启，只有实时翻译主开关开启时才生效。它适用于青简能够识别的 macOS 应用；密码、登录等私密输入环境不启用。无法识别应用时不启用草稿。Windows、Linux 暂未实现此草稿模式，保留既有输入方式。

本机地址只允许指向当前电脑，与「云服务」页的模型、密钥和开关分开，不回退到云服务。字词释义所选的学习语言不改变整句中英互译方向。

在未使用草稿模式的应用里，普通实时翻译浮窗显示且没有待选拼音时，单独按 `Esc` 会清空当前翻译并收起浮窗，正在进行的翻译也会取消。应用中已输入的原文保留；继续输入后重新开始翻译。正在选字时，`Esc` 仍先按原有规则取消拼音或折叠候选；草稿模式仍使用已配置的草稿取消键。

## 微信独立翻译草稿窗

目前用户已验证：将微信加入「不使用草稿的应用」，并把拼音显示设为「行内和候选窗口」（`preedit=both`）时，普通输入可正常选字上屏。只在候选窗口显示拼音（`preedit=window`）时，仍有原始字母残留。

下面是独立翻译草稿窗的测试入口，设计上先在青简中编辑原文并翻译，再输出到微信。它的实际自动激活与获取键盘焦点尚未通过验证，不能视为已经可用的微信翻译方案。

开启「实时中英互译」后，在微信输入位置使用开窗快捷键，或在已显示的翻译条中点击「打开草稿窗」，先开窗再开始输入；快捷键缺省 `⌃⌥E`，可在「设置 → 快捷键 → 本地实时翻译 → 打开翻译草稿窗」修改。无需开启原有「翻译草稿模式」，也不会自动截取开窗前的首个按键。当前先适配微信，Terminal 保持原有输入路径。

开窗时暂时无法确认目标输入框，也可先在独立草稿窗中编辑和翻译；输出时再回到目标输入框，按提示用开窗键明确确认当前位置。

在草稿窗内继续输入或切换高亮候选时，译文持续修正。原文输出和取消沿用草稿动作设置，缺省 `Enter` 输出原文、`Esc` 取消；译文输出沿用已有快捷键（例如已设置的 `⌘⇧Y`）。输出仅将文字填入微信，不自动发送消息。首次输出若无法确认原输入框，窗口会保留草稿并提示回到目标输入框，再按开窗快捷键确认填入。等待确认时修改草稿会使这次待输出内容失效，需重新触发输出；若仍无法确认，可复制译文后手动粘贴。目标丢失或焦点不明确时不会将文字写入其他应用，也不自动发送。

独立草稿窗显示期间，应用内原有的候选窗与翻译条会收起，不同时显示两个浮窗；草稿的选字和输出快捷键由独立窗口处理。点击其他位置离开草稿窗时，窗口隐藏、内容保留，不自动输出；回到输入位置再次按开窗键可继续编辑。若正在等待确认填入，同一应用内的旧草稿输出快捷键也不会另行输出其他内容，请按提示使用开窗键确认；在应用中继续输入普通文字会撤销这次待填入确认，按应用原有方式输入，独立草稿仍保留。

等待确认时，按译文输出键（如 `⌘⇧Y`）或原文输出键（缺省 `Enter`）只提示确认位置，不输出旧稿；按取消键（缺省 `Esc`）可直接取消整稿，即使此前在窗口内按住的键已在别处松开，也不会因此卡住取消。

切换到 Terminal 等其他应用时，独立草稿窗隐藏，未输出内容仍保留，但本次待填入确认撤销；Terminal 可继续使用原有草稿方式。返回微信后再次开窗可继续原稿，并需重新选择输出。取消独立草稿或关闭实时翻译后，原有输入方式恢复；开窗失败不会替你提交或丢弃应用内已有草稿。

开窗快捷键仅接受修饰键加英文字母，录制时 `Backspace` 禁用，`Esc` 或点击别处取消录制。与已有动作冲突时仅停用开窗快捷键，已有译文输出等动作保留，可重新设置开窗键。

## 翻译草稿模式

以下说明为应用内草稿路径，与手动打开的独立草稿窗分开。微信目前按上文已验证的排除草稿与行内显示配置使用。

自动翻译条在没有原文或待选输入时收起，有可恢复草稿、可用开窗入口或提示也不会单独弹出空窗。普通实时翻译同样不会仅因输入纯数字、标点或 emoji 而出现翻译条。

翻译草稿模式从字母、拼音或汉字开始暂存原文，不直接填入应用。真空态的数字、标点、空格和 emoji 直接交给应用，不隐藏暂存，也不加入之后的草稿。例如连续输入 `123abc`，`123` 已进入应用，只有随后启动的 `abc` 属于草稿。已开始草稿后，数字、标点、空格和 emoji 继续归入整稿；即使删到只剩数字或空格，草稿也仍然显示，直到删空、输出或取消。表达式、问字入口和符号面板继续按原有方式操作。

浮窗同时显示原文和译文；已确认文字加上当前高亮候选一起预译。继续输入、切换候选或退格时，整段译文重新调整。组句中的空格、数字和方向键仍可选字。手动打开的独立草稿窗不受首键规则限制，可以从数字、标点、空格或 emoji 开始编辑。

停止敲键约 180 毫秒后请求翻译，实际等待时间取决于电脑与模型。等待新译文时保留上次成功译文并标记「更新中…」；旧结果不会覆盖新文字。草稿保留整段原文，句末标点不切断草稿。未写完的内容缺少上下文，模型可能误判；中英混写时按整段主要语言推断方向。

浮窗提供以下操作：

| 操作 | 作用 |
|---|---|
| 复制译文 | 复制当前显示的完整成功译文，包括更新中或失败后仍保留的旧译文 |
| 输出译文 | 完成选字、等待当前整段最新译文后，一次填入应用；更新中或失败时不能用旧译文输出 |
| 输出原文 | 输出已确认文字加未选原始按键，不采用高亮候选、不展开双拼；「今天」加 `shi` 输出「今天shi」 |
| 粘贴到草稿 | 已有草稿时按 `⌘V`，将剪贴板纯文本追加到原文末尾并重新翻译；有待选拼音时先完成选字 |
| 取消草稿 | 一次丢弃当前整段草稿和拼音，不向应用填字 |
| 恢复草稿 | 取回当前应用最近保存的一条草稿，只恢复到青简并重新翻译，不直接填入应用 |

缺省 `Enter` 输出原文，缺省 `Esc` 一次取消整段草稿。输出原文或译文均不自动发送消息，也不自动执行命令。输出后草稿清空，检查内容后再次独立按 `Enter`，才按应用原有方式提交。空态控制键和导航键交给应用。

译文输出快捷键缺省为 `⌃⌥V`，已有自定义组合（如 `⌘⇧Y`）保留。原文输出和取消可分别在「设置 → 快捷键 → 本地实时翻译 → 输出草稿原文／取消整段草稿」修改，支持单独 `Enter`、单独 `Esc` 或修饰键加英文字母。录制这两项时 `Esc` 会被录入，点击别处取消录制，`Backspace` 禁用。

原文输出快捷键改键或禁用后，原 `Enter` 仅保留选字或提示；整稿取消快捷键改键或禁用后，原 `Esc` 可取消待选拼音或折叠候选，但不再取消整段草稿。冲突快捷键会提示，不会同时执行两个操作。

普通 `⌫` 先删待选拼音／字母，再删已确认原文末字。浮窗显示待选按键与光标；高亮汉字可能暂时不变，不能只看候选汉字判断是否删除。长拼音显示光标附近部分，以 `…` 标记省略。本说明不改变向前删除键或带 `⌘`、`⌥`、`⌃` 的删除操作。按住退格删空后，需先松开，再次空态退格按应用原有方式处理。

草稿只支持单行、尾部追加、退格和选字，不是完整编辑器。两种输出的换行转为空格，其他不可见控制字符会被拒绝；复杂导航会提示并保留草稿。需要多行时可按应用关闭草稿模式。没有草稿时，`⌘V` 仍交给当前应用；草稿不会导入应用中已有的文字。

## 按应用关闭草稿模式

打开「设置 → 中英文 → 本地实时翻译 → 不使用草稿的应用」，每行填写一个完整应用标识，例如：

```text
com.apple.Terminal
com.apple.Safari
com.tencent.xinWeChat
```

点击「保存排除列表」，或离开输入框保存；`Enter` 在列表中换行，`Esc` 放弃未保存更改。留空并保存可清除排除列表。列表精确匹配、区分大小写，不支持通配符；重复项只保存一份。

被排除的应用沿用直接输入与普通实时翻译方式，不先留在青简草稿中。若所有应用都需要直接输入，可关闭「翻译草稿模式」，实时翻译主开关仍可保留。


## 粘贴到当前草稿

已有草稿时，按 `⌘V` 将剪贴板中的纯文本追加到当前原文末尾，并重新翻译；英文会按文字保留，不会当成拼音按键。粘贴只改变青简草稿，不会同时填入当前应用。没有草稿时，`⌘V` 保留当前应用原有粘贴行为，不会新建隐藏草稿。

有待选拼音时，请先完成选字再粘贴；这时按粘贴键只提示，不会把文本漏入应用。剪贴板为空或没有纯文本时保留草稿并提示。CRLF、CR 和 LF 换行转换为空格；制表符等不支持的控制字符会使整次粘贴被拒绝，不会只粘贴其中一部分。

快捷键可在「设置 → 快捷键 → 本地实时翻译 → 粘贴到草稿」录制为修饰键加英文字母；录制时按 `Backspace` 禁用，`Esc` 或点击别处取消录制。禁用后不会向草稿粘贴；没有草稿时 `⌘V` 仍按应用原有方式处理，已有草稿时沿用草稿模式的组合键保护。与已有动作冲突时会提示，请改用其他组合；已有译文输出键（如 `⌘⇧Y`）保留。


## 切换应用与恢复草稿

切换应用、焦点或鼠标输入位置时，未输出的已确认文字与原始待选按键可暂存。只保存在当前青简进程的内存中，所有应用合计最多 16 条，不写磁盘；超过上限会淘汰较旧记录。

回到原应用后，从输入法菜单选择「恢复当前应用草稿」，取回该应用最近保存的一条；已有翻译浮窗时也可点击「恢复草稿」。空态不会为显示恢复按钮而弹窗。只针对当前应用，其他应用的草稿不会被取出。青简不能可靠辨认每个输入框，因此不会自动恢复或直接填字；请先确认输入位置。当前已有草稿、拼音或其他待处理输入，处于私密环境、没有可恢复内容，或独立草稿窗持有输入控制权时，菜单恢复项不可用，避免覆盖。待选部分可能按原始拼音按键恢复，需要重新选字；恢复失败时不输出，仍保留存档。

取消当前草稿不会删除其他已存草稿。关闭实时翻译主开关、进入私密或登录环境、退出青简会清除存档；切换输入方案、内置英文模式开关、Shift 字母处理等影响按键解释的设置也会清除。其他设置变更会先保存当前草稿，不自动恢复。输出写入前若因输入位置变化而被拒绝，未写出的内容也可能留作恢复；以浮窗提示为准。

## 键盘权限与快捷键

草稿的键盘接管只在前台应用使用青简、实时翻译与草稿模式开启、应用未排除且当前有草稿或待选按键时生效，私密环境中停止。空态、离开输入环境或关闭功能后恢复应用原有按键行为。

若浮窗提示接管不可用，请按提示检查「系统设置 → 隐私与安全性」中青简的相关授权，包括辅助功能、输入监控；具体以系统实际允许为准，不表示仅开启其中一项就一定可用。青简不会自动弹授权框或打开设置。安装更新后若旧授权失效，可按当前版本重新授权；必要时在辅助功能中移除旧条目并添加当前安装的青简。

重新激活前可先复制译文或输出原文；切换输入环境可暂存草稿，返回后可从输入法菜单选择「恢复当前应用草稿」。接管被系统暂停时不盲目自动恢复，按浮窗提示重新激活重试。原文输出和整稿取消的键盘入口不可用时，只提示并保留内容，不输出或清空；对应按钮仍可使用。

系统输出热键按 ABC／QWERTY 物理字母键位登记，其他键盘布局的按键位置与键帽可能不同；支持 `⌘⇧Y` 等组合，但不保证所有已占用组合都可登记。登记失败时浮窗显示原因与系统状态码，仍可点输出按钮。解决冲突后重新激活青简或关闭再开启草稿模式可重试。译文输出快捷键同样需完成选字并等待最新译文，不能强制输出旧结果。

## 复制与手动替换

关闭草稿或排除某个应用后，可继续使用普通实时翻译；原文已填入应用时，复制当前显示的成功译文，或按需开启「允许用译文替换选中内容」。先取得整句译文，再选中完全对应的原文，点击「替换选中内容」或按 `⌃⌥R`；无需重新调用模型。

选区必须与已有译文的原文完全一致，包括标点和空格，不能只选一个词却用整句译文覆盖。无选区、不匹配或应用不支持范围替换时提示并保留原文，仍可复制。macOS 自带 Terminal 不支持此选区替换；终端历史输出通常也不可编辑。

同一输入环境选中文字时，可保留当前显示的成功译文供匹配；切换应用或私密状态后不跨会话复用。在「中英文」点击「修改替换快捷键」可定位已有录制器。复制与替换缺省 `⌃⌥C`、`⌃⌥R`，录制时 `Backspace` 禁用；禁用快捷键不影响按钮。

## 什么时候开始下一句

以下规则用于关闭草稿的普通实时翻译，草稿模式始终保留整段。

- `。`、`.`、`?`、`？`、`!`、`！` 与明确换行结束一句。
- 逗号、分号、冒号和顿号不结束一句。
- 小数、常见英文缩写、网址和邮箱中的点按上下文判断，例如 `3.14`、`Dr. Smith` 不因中间的点切句。
- `…`、`……`、`...` 暂不切句；连续 `?!`、`!!!` 作同一组，紧随的引号和右括号归入前一句。

连续输入中删除句末标点，可恢复前一句继续翻译。缩写与网址判断不能覆盖所有写法。普通模式遇到无法确认的外部编辑时会停止连续追踪；Terminal 仅按受控连续输入与候选累计，不把屏幕回显当作 Codex 等终端界面的真实编辑内容。

## 服务不可用与诊断

Ollama 未启动、模型缺失或请求超时不阻塞选字，可等待重试，或用「输出原文」保留原文。当前句只发送到本机 Ollama，不云端回退。

保持默认日志级别即可排查。日志中 `live_translation` 记录包含应用标识、范围、长度和重置／拒绝原因，不包含输入或译文正文。`Partial`、`Unreadable` 表示局部或不可读信息，不据此声称已读取应用完整文字；系统事件记录也不等于已通过目标应用的实际操作验证。
